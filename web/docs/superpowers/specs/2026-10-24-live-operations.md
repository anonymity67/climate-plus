# Persistent water operations, GPS and pollution workflow

User correction: the v0.3 site is retrospective/browser-only and cannot be presented as an operational backend. Build a complete frontend/backend/database MVP, persistent field inputs, explicit evidence/reasoning, live opt-in device GPS, server routing and alternatives around reported blockages, polished pollution workflow and a portable end-to-end development package. Do not narrow this to another static map or label simulated movement live.

## Architecture

Keep existing React/Leaflet interfaces and science. Migrate the hosted Site to the supported Vinext full-stack starter and Cloudflare D1 (SQLite). Shared plain-JS backend and routing modules are testable with Node 24 SQLite. App Router API handlers adapt the trusted dispatch-owned ChatGPT identity and D1 binding. Local development uses the starter's Miniflare SQLite/D1 and documented local sign-in. The existing Site audience stays unchanged.

Live operations is the first task; historical inventory and publisher context are data libraries, not current safety determinations. The Dacope assets/hazards are representational. Its actual road geometry becomes a deterministic routable graph with topology/coverage checks. Current travel restrictions, traffic, bridge capacity and water safety are not established by that graph.

## Identity, collaboration and privacy

All operational records are owned by the signed-in Site user; another user cannot read them without explicit trip membership. The trip owner can create expiring, role-scoped invitations; only token hashes are stored. An invite cannot bypass the Site's own access policy. Roles: owner, supplier, recipient, viewer. GPS is visible only to trip members. GPS capture requires an explicit start action/browser consent, has a visible stop/delete action and stale state, and never starts automatically. A replay is a separate trip mode and mutation endpoint, clearly labelled representational.

No client-chosen owner IDs, fake admin identities in production, automatic lab verification, public precise-GPS endpoint, embedded secrets or private observations in the public catalogue. Local starter mock identity is only for loopback development and excluded from production.

## Shared routing interface

`routing/engine.mjs` exports `createRoutingEngine(graph)`, returning:

- `metadata`: source/graph hashes, graph version, road/node/edge counts, bounds and limitations.
- `route({ origin, destination, closures = [], assumedSpeedKmh = 25, profile = 'road' })` returns `{status, routes, snap, excludedEdgeIds, source, warnings}`.
- `pointAlongRoute(route, distanceM)` returns `{latitude,longitude,heading}` or null for no route.

Coordinates are objects `{latitude,longitude}`. A closure has `{id,edgeIds?:string[],geometry?:GeoJSON,radiusM?:number,latitude?:number,longitude?:number}`; only active, appropriately scoped closures reach this engine. Every returned route has `{id,distanceM,durationS,edgeIds,geometry,edges}`, with GeoJSON LineString geometry and each edge `{id,name,coordinates,lengthM,highway}`. IDs are deterministic, routes obey exclusions, and the alternative must be a distinct valid path, not a recoloured primary. Explain if none exists. Alternative generation may use shared-edge penalties rather than claim exact second-shortest routing. No straight-line fallback is called a road route.

Reject invalid coordinates/speed, start/end beyond a justified snap distance, disconnected paths, unsupported graph and unusably small graphs. Separate endpoint-to-network snap distances from routed distance/time. OSM one-way fields in the supplied extract are all absent; explicitly declare bidirectional inference. Preserve grade separation at crossings and document endpoint connection assumptions. Profile `road` must not silently price footpaths at vehicle speed; conservative type exclusions/speeds need explicit rules and tests.

## Shared backend interface

`backend/api.mjs` exports `createApi({store,routing,catalogue,clock?,uuid?})` returning an async function `(request, actor) => Response`. `actor` is `{id,displayName?,email?}` from a trusted server adapter or null. The request URL is `/api/...`. Store interface: async `get(sql,params=[])`, `all`, `run` (returns changes), `batch([{sql,params}])`. Implement D1 and Node SQLite adapters. All SQL is parameterized, migrations own schema; no schema creation during hosted request handling.

Poll live snapshots every 3 seconds, show sync age and a stale/offline banner; recalculate route when fixes/closure revision changes. Position capture is throttled, timestamped and aborts cleanly. Maximum 100 fixes/role and 24-hour visibility, lazy pruning on writes and date-filtered reads. Handle retries/idempotency, unauthorized IDs, wrong-role invites, cross-origin mutations, invalid units/dates, oversized input and unreachable routes. DB event history provides an auditable source/reason trail without presenting it as field truth.

## Resident and operator UX

Operations: create trip from labelled presets or explicit coordinates, see primary/alternative distance/time and estimation assumptions, select route, click a segment and report a blockage with reason/expiry, clear it, replay a demonstration, or opt in to actual device sharing. Owner invitation controls make cross-device collaboration testable. No GPS or ETA is labelled live when replayed/stale/outside graph coverage.

Pollution: fresh server-backed observation form and case workflow, source/reason drawer, explicit fisheries objective profile, missing-data and QA flags, review history and export. Keep old repository data and Kaggle context accessible as historical/reference layers. Zero objective failures, low publisher class and a nearby well never establish drinking-water safety. No app-inferred safe/unsafe well designation; only attributed, dated source assertions with clear verification state.
