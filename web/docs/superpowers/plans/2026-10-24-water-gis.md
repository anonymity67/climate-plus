# Water access and GIS implementation plan

> Execute inline with the executing-plans skill; keep decisions and checks in the implementation ledger.

**Goal:** A usable, evidence-labelled water-access and pollution GIS MVP incorporating the supplied Dacope QGIS network.

**Architecture:** Extend React with a GIS workspace and focused Leaflet map components. Pure JavaScript handles distance, evidence status, filtering and scenario lineage. Deterministic Python adapters preserve and normalize versioned public snapshots.

**Stack:** Existing React/Vite/Leaflet; Node tests; Python standard library where practical.

**Spec:** `docs/superpowers/specs/2026-10-24-water-gis-design.md`.

## Global constraints

No unverified water point is called safe. Historical/classified/synthetic data remain distinct. No inferred plume or flood-safe route. Preserve existing Site audience, baseline measurements and frozen DO evaluation. No secrets in source or outputs.

## Review focus

Invalid/missing coordinates; stale/missing/future dates; zero/no search results; synthetic nodes mistaken for public supplies; publisher intensity classes mistaken for current lab results.
