# Private operations API ·3.0

`createApi({store,routing,catalogue,clock?,uuid?})` from `backend/api.mjs` returns `async(Request,trustedActor)=>Response`. Production identity is supplied by the authenticated Sites gateway through `app/chatgpt-auth.ts`; caller identity fields are never accepted as authentication. Local loopback test headers are a test boundary, not a production login.

`createD1Store(binding)` is the Worker adapter. `createSqliteStore(DatabaseSync)` is the Node24 adapter. Both implement asynchronous `get`, `all`, `run` and atomic `batch`. Apply schema migrations externally; no request executes DDL. See `db/schema.ts`, `drizzle/` and [DEVELOPMENT](DEVELOPMENT.md).

The production adapter uses `routing/registry.mjs`: five statically bundled server graphs and scenario catalogues, with no Worker filesystem access. Its pool is `{metadata,regionIds,forRegion(id),scenarioForRegion(id)}`; `metadata` describes default Dacope, and the lookup methods return the regional engine/scenario or `undefined`. `createApi` also accepts the original single routing engine for Dacope-only integrations. Apply all ordered `drizzle/*.sql` migrations: `0001_regional_trips.sql` appends non-null `trips.region_id` with default `dacope`, preserving existing trips and leaving the applied `0000` migration unchanged.

## Transport

JSON responses use `Cache-Control: private, no-store`. Mutations require Origin matching request URL origin, reject cross-site fetches, and bound JSON bodies to32KiB. ISO timestamps, real dates, WGS84 coordinates, numeric ranges, strings, evidence URLs, roles and graph edges are validated. DELETE also requires Origin. Error envelope: `{error:{code,message,details?}}`.

Statuses:400 invalid input;401 sign-in required;403 origin/role rejected;404 absent/inaccessible record;409 stale edit, duplicate/expired invite, nonmonotonic fix or unavailable preference;413 oversized body;415 wrong media type. Internal errors do not expose SQL/private rows. Unauthenticated responses point to `/signin-with-chatgpt?return_to=/`.

Trip mode is `operational` or `replay`. `regionId` is `dacope`, `ukhia`, `chattogram`, `khulna` or `tongi`; omission defaults to `dacope`, while unknown, empty or null values return400 `invalid_region`. A trip's region is fixed at creation. Endpoints are `{latitude,longitude,label,provenance}`. Coordinates outside the chosen road network produce the existing off-graph/no-route result rather than switching regions. Profile is `road`, default assumed speed25km/h, range1–80. Role names: owner, supplier, recipient, viewer; invite creation permits the latter three. Invitation lifetime1–10080minutes; tokens are cryptographically random, hashed in DB, single-use and returned only at creation. Existing/expired/concurrently consumed tokens409. Site access policy still applies.

Trip DTO fields: id, ownerId, name, mode, regionId, origin, destination, assumedSpeedKmh, profile, selectedRouteId, replayDistanceM, revision, createdAt, updatedAt, membershipRole. Snapshot latestFixes is an array with at most one latest visible fix per role; it is not an object keyed by role.

`POST /api/scenario-route` serves the primary map without requiring an authenticated private-operations actor; the Site's existing audience policy still applies. It accepts only the selected region's bundled scenario roles and graph edges, using the same pure `calculateScenario` function as local playback. Required `hazard` is `clear`, `storm` or `salinity`; optional `severity` is `moderate` (default) or `severe`. Required `destinationRole` must exist in that scenario. Optional `blockedEdgeIds` defaults to `[]` and permits at most100 known regional edge IDs. Missing/unknown regions, hazards, roles and malformed or foreign edges return400; an integration without a bundled scenario returns404 `scenario_unavailable`. Same-origin, JSON/body-size and spoofed-identity guards apply. Responses include `regionId`, `calculation:'server'`, `hazard`, `severity`, `sourceKind:'representational'`, `origin`, `destination`, actual routes/edges, `activeHazard` and `heldAssetIds`. Full graph edge-ID metadata is omitted. This endpoint neither reads nor writes the private database and does not change trip authentication requirements.

## Positions and routing

Device payload: `{role,source:'device',clientFixId,latitude,longitude,accuracyM,speedMps?,heading?,capturedAt}`. Roles supplier/recipient only. Server accepts captures no older than120seconds and at most30seconds future skew; the browser wrapper is stricter at10seconds future. Capture timestamps strictly increase per role. Same retained clientFixId with identical content is idempotent; different content409. Concurrent retries produce one row/event.

Only device fixes captured in the last30seconds with accuracy≤100m replace configured routing endpoints. Replay, stale and low-precision positions remain labelled. `positionUse` explains each endpoint: used, reason, source, capturedAt, accuracyM. Used means supplied to the routing engine, not proof of route success. A fresh off-network fix yields `off_graph`, no selected ETA, no invented straight-line road.

Routes contain id, distanceM, durationS, edgeIds, LineString geometry, ordered edge details and method. The enclosing result includes `regionId`; route computation, closure validation and replay interpolation all use the trip's regional engine. Metadata in `source` omits the full graph edge-ID list, while route-specific `edgeIds` and excluded edges remain available. Status and warnings must be checked. `snap` reports actual endpoint gaps; they are excluded from distance/time. See [ROAD-GRAPH](ROAD-GRAPH.md) for topology and speed assumptions. Current traffic, flood/bridge safety and water quality are unverified.

Visible fixes have a24-hour read horizon. Writes lazily prune that trip/role to100fixes and remove older than24hours. Old idle rows remain physically until a subsequent role write but are hidden from snapshot/route/export. Delete removes all role history and atomically advances a timestamp watermark to at least server stop time: delayed captured-before-stop uploads cannot resurrect it; newer captures may resume. GPS audit events contain roles/times, not raw coordinates. Browser UI stops watch immediately, waits for in-flight publish, then requests deletion, and exposes unconfirmed failure/retry.

Active closures are same-trip, unrevoked and unexpired. API supports≤100 edge IDs from that trip's regional graph; a foreign region's edge returns400 `invalid_edges`. Point radius is1–2000m (default30), expiry1–1440minutes. Reports retain sourceKind/sourceLabel and `verification:'unverified-report'`; replay reports are representational. Engine-only polygon support is documented separately; it is not silently exposed as an official flood feed. Preference fallback occurs if current geometry invalidates the chosen ID.

Trip revision increments on persisted mutation. Time alone can expire a closure or stale a fix without incrementing revision; clients refresh route every polling cycle, approximately3seconds. Replay advances only on explicit request; revision gates prevent concurrent failed advancement from inserting telemetry. It never becomes device-source GPS.

## Observation and case integrity

Observation fields: date, latitude, longitude, optional location/river, at least one ph/do/cod, explicit `units:{do:'mg/L',cod:'mg/L'}` for corresponding measurements, required `metadata:{sourceKind,sourceLabel,method?,evidenceUrl?,sampledAt?}`. SourceKind is field-entry or representational. SourceLabel is attribution, not independent authentication. Invalid/future dates, coordinates, units and empty panels are rejected.

Immutable entered content and metadata receive canonical SHA-256`contentHash`. Server calls existing `validateObservation`/`screenWater`. Screening is partial inland-fisheries objectives only; hashes do not establish sample collection, custody or authenticity. Returned status is entered-result-not-authenticated-lab-evidence. No endpoint infers a safe well.

Case stages: new, sampling, reviewed, follow-up, closed. Updates and audit are atomic. Concurrent changes and stale provided expectedRevision return409. UI sends loaded revision, preserves drafts on external changes, and offers explicit refresh on conflict. Explicit note:null clears a note; omitted note retains it. Reviewed means operator review, not laboratory certification. Private entries never enter the public catalogue automatically.

## Verification boundary

`node --test tests/backend*.test.mjs` exercises actual SQLite/Miniflare D1, ordered migration upgrades with pre-existing Dacope trips, schema equivalence, restart persistence, rollback, identity/membership, invite races, validation, retention, deletion barriers, replay concurrency, stale/concurrent case edits, five-region route/closure/replay isolation and off-graph withholding. Stateless scenario tests compare all five regions across clear/storm/salinity against the shared calculator, reject cross-region edges and verify zero database access. `npm run smoke:local -- http://127.0.0.1:5191` exercises the built HTTP adapter. These do not establish hardware GPS precision, physical access, sample authenticity or water safety.
