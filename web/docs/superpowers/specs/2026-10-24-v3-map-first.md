## Product decision

One map-first interface: select Dacope/Ukhia/Chattogram/Khulna/Tongi, choose normal/storm/salinity, play a clearly labelled delivery scenario, apply/remove a road blockage, inspect a point and add/import pollution observations on the same map. Advanced private trip/GPS/case workflows remain reachable through secondary disclosure, not eight competing navigation items. Preserve backend/database, source rights and existing Site audience.

Approaches considered: translating Dacope geometry was rejected because it would misrepresent other regions; public inventory-only pins were rejected because they lack a response network. Chosen: repeat the service-point role template on each region's actual sourced road graph, retaining representational labels for invented service assets/hazards. Real pollution and historical water-point coordinates never move. Dataset absence remains explicit.

His handoff explicitly calls assets/hazards fictional on real OSM roads. It supplies interactive scenario selection, not authenticated live telemetry. ## Data interfaces

`public/data/regions/index.json`: `{schema,regions:[{id,name,center:{latitude,longitude},bounds:[west,south,east,north],graphUrl,scenarioUrl,source:{...}}]}`. IDs: dacope, ukhia, chattogram, khulna, tongi. Display name Chattogram (Chittagong). Each graph has the existing routing/engine.mjs schema and identical public/server bytes at `public/data/regions/{id}-graph.json` and `backend/data/regions/{id}-graph.json`.

Scenario JSON `public/data/regions/{id}-scenario.json`: `{schema,regionId,assets:[{id,role,name,latitude,longitude,provenance:'representational',sourceLabel}],hazards:{storm:{moderate:GeoJSONFeature,severe:GeoJSONFeature},salinity:GeoJSONFeature},closures:{storm:{moderate:{edgeIds:[...]},severe:{edgeIds:[...]}}},source:{...}}`. Asset roles include supplier,reserve,pump,pond,school,crew. Dacope reuses supplied asset coordinates and hazard polygons; other-region service roles/hazard areas are declared scenario templates located on real local roads. Edge-only closures represent declared scenario effects, not a measured flood model. Every region needs a connected baseline and a demonstrated distinct closure detour where its graph permits one; failure/no-route is explicit.

Regional server routing pool: `{metadata:defaultDacopeMetadata,regionIds:[...],forRegion(id):RoutingEngine}`. Existing engine contract remains `route(input)`, `pointAlongRoute(route,distanceM)`. `createApi` remains compatible with a single engine in legacy tests; real adapter uses pool. Append `trips.region_id` default dacope via a new schema-only migration. Trip payload/view gains regionId, validates known region and uses its engine for route/closure/replay. Catalogue adds regions and regionId on assets; never validates one region's closure edge in another.

Pollution module `src/mvp/pollution-vectors.mjs`: `buildPublishedVectors(waterEvidence,riverContext,bounds)` returns `{features,counts}` with coordinate-preserving, latest-per-site historical measured features and separate publisher-context features; `parsePointUpload(text,options)` validates bounded CSV/GeoJSON and returns `{features,observations}` or explicit row errors; `observationsToFeatures(rows,bounds)` maps private saved observations. Imports require real coordinate/date and attribution; numeric DO/COD units must be explicit (CSV do_mg_l/cod_mg_l or GeoJSON units). SourceKind field-entry versus representational must be declared. No source, potability, industrial blame, sample date or affected-area radius is invented.

## Acceptance

- Same visible calamity/point/route/playback workflow works in five genuine road regions; selected region changes every data layer coherently.
- Actual source rows/queries/snapshot timestamps/rights/hashes and deterministic builders are included. No runtime Overpass dependency or tile prefetch.
- Route blockages affect graph geometry; distinct alternative and no-route behavior are tested. Changing region/hazard resets playback and old selection/closures.
- Playback never becomes device GPS. Opt-in device tracking is separately labelled, stops on exit and preserves existing private sharing/delete semantics in advanced tools.
- Pollution point input exists, maps valid data immediately, can save through authenticated API, and exports GeoJSON. Wrong region, malformed/out-of-range values and unavailable source data are handled visibly.
- Initial view is a map, one primary playback action and a compact point/route panel; no old dashboard sidebar or scientific tool wall. Keyboard/mobile remain usable.
- Full tests/build/data hashes, browser desktop/mobile workflow, regional HTTP API, fresh clean archive install/migrations/build/smoke, preserved hosted audience and final source/ZIP integrity are verified.

## Scope boundaries

This demonstrates expandable architecture, not national road coverage, safe drinking water, verified current calamities, real transport fleet availability or field impact. Region extents are explicit. OSM access/condition completeness and modelled ETA remain unverified. Historical pollution data stays historical; unknown current conditions stay unknown.
